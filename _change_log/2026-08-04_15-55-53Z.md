Review of 868a5b9..HEAD (drag-to-resize). Fixed:

1. **Refused resize left the screen ahead of the store.** `ControlsActions.resizeNode` reported `store-unchanged` on a refusal (no stable id / path gone), so no rebuild ran — but the release had already left the dragged box in React Flow's LOCAL node state, so the graph kept showing a size nothing stored, under a notice saying it could not be saved. `GuardedWriteOutcome` gained a third value, `store-unchanged-screen-ahead`; `guarded()` repaints on everything but `store-unchanged`, and `persistOutcome` now takes the refusal outcome from its caller (a pin's refusal still skips the rebuild). Two ControlsActions tests changed assertion accordingly.

2. **`VicinityGraphFlow` reseeded local nodes from a `useEffect`.** `edges` is a plain memo, so every publish committed one frame of NEW edges against the PREVIOUS build's nodes before the effect caught up. Replaced with React's render-phase adjustment (`seededFrom !== mappedNodes`), so the two props can never disagree.

3. **Docs stated the opposite of what shipped.** README ("per-note ... overrides come later, if at all", "no per-note settings") and high-level-plan ("Sizing is global-only in V1", layout-stability threshold described on `sizePx`) truthed up; README gained a "Node size" section and the two interaction bullets. CLAUDE.md's runGuarded line names the new outcome.

4. `nodeSizeOverridePx` in graphIdentity is now the ONE reading of `override.sizePx` (flowMapping's `hasSizeOverride` went through it); `NodeMenuRequest.entries` is a non-empty tuple type instead of a comment; the e2e drag helper measures the handle AFTER hovering it.

Filed nid_y8axtvcum3wvljzv3d3p8cwd1_e for the pre-existing unread `FlowNodeData.sizePx`/`sizeScore` fields.
