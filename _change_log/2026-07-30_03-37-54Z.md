Step 5 of the settings-cleanup chain (ticket nid_x6hgehsu5il1d1shuraz3ufqy_e, closed).

## Why
Settings tests hand-enumerated expected values (`toEqual` over every field), which went STALE
twice (both symptom tickets now resolved) and, worse, could not catch a field that was declared
in the spec but never wired into parse/reset/bounds. Three separate suites mirrored the same
defaults, so a legitimate default change meant hunting down every mirror.

## What changed
- `src/engine/SettingsSpec.test.ts` and `src/engine/forceLayoutSettings.test.ts` rewritten as
  SPEC-ITERATING suites: one walk over `SETTINGS_SPEC` drives parse / global round-trip /
  reset-to-declared-default / bounds (below-min, above-max, garbage -> declared default), with
  min/max read FROM the descriptor rather than restated.
- New `src/engine/settingsProductDefaults.test.ts` is the ONLY place literal defaults and ranges
  may be written -- id-keyed over every spec leaf, plus two justified range pins.
- `src/view/settingsRowParity.test.ts` strengthened: comment-stripped, module-keyed scans plus a
  genuine per-row label check.
- ONE production line: `clampOutlineMaxDepth` now resolves NaN to the spec default via the
  existing `clampIntoRange` (a real inconsistency the new bounds test surfaced; finite-input
  behavior unchanged).
- Global-only, per the 2026-07-29 owner scope change -- no per-doc override tests.

## Teeth proven, not assumed
Verified by mutation, independently reproduced by the reviewer:
- Adding an unwired field to `SETTINGS_SPEC` reddens 9 tests across 4 files, each naming the field.
- All 17 spec mutations redden; "mutations with NO tripwire" is empty.
- Mutating any single default fails EXACTLY ONE file / ONE test, so one table replaced three mirrors.
- A per-row label skip in EITHER presenter, a walker skip, or a commented-out control-kind `case`
  each redden the parity guard by name.

Worth remembering: the first parity scan spread `{...PRESENTERS, ...SECTION_WALKERS}`, which share
the key "controls panel" -- the collision silently dropped the panel presenter and the mutation
PASSED. Now module-keyed with a vacuity guard. A guard is only as good as what it guards.

## Tests
87 files / 1139 -> 91 files / 1160, all green (`it` counts collapsed where a walk replaced
per-field cases). `npm run check` clean. No e2e spec touched, no React render harness introduced.

## Open owner decision
The ticket asked for a SMALL literal set; what shipped pins all 21 spec leaves, because a curated
subset provably left three defaults (including `linkStrengthFactor` max 4 -- the value that drifted
twice) with zero tripwire, and only a total table detects an added/removed leaf. That is a deviation
from an explicit instruction: filed for ratification or trim as nid_5rdya0nr660n9sru1zhfs51ic_e (`decide`).
