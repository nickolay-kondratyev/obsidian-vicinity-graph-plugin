Review of 868a5b9..HEAD, third round (rounds 1-2 are 2026-08-04_15-55-53Z and 2026-08-04_16-14-33Z). Both fixes were captured as FAILING e2e tests first.

1. **Only the corner chip was ever grabbable.** `NodeResizeControl`'s Line variant is a 1px-WIDE box (`.line.right { width: 1px }`) centred on the node's edge, in FLOW units — a fraction of a screen pixel below zoom 1 — and React Flow `autoScale`s only the HANDLE variant against zoom. Probed with a real pointer: `grip.hover()` fails with `.vicinity-graph-node intercepts pointer events`, so 'drag a node's right/bottom edge' (README, *Node size*) never worked. FIXED in CSS only: the line control becomes an 8px grab BAND straddling the edge with the accent line drawn by a pseudo-element (widening the box alone would push RF's border half a band off the edge it marks), and every grip gets `z-index: 1` — the grips are EARLIER siblings of `.vicinity-graph-node`, so at `z-index: auto` the node body painted and hit-tested above every half of a grip overlapping it. Gated by a right-line drag in e2e/nodeResize.e2e.ts (width grows, height does not).

2. **A node click wrote React Flow's SELECTION into the controller's node state.** Wiring `onNodesChange` for the resize also handed RF its selection bookkeeping: `addSelectedNodes` -> `applyNodeChanges` -> `selected: true` -> the focus ring in graph-view.css, on a read-only graph whose only node states are MAIN and pinned-central (`REACT_FLOW_GLOBAL_KEY_BINDINGS` nulls the multi-select modifier for exactly this reason). It sticks until the next publish — and clicking the CURRENT main publishes nothing. FIXED: the callback applies `dimensions` changes only, so the seam admits exactly the change it was added for and every future RF change type stays out. WHY-NOT `elementsSelectable={false}`: RF couples edge cursor and focus stroke to `.selectable`.

3. Docs: `SettingsWritePipeline.runGuarded` still said its guarded writes were 'today the pinned set'.

4. nid_sj9qg27cmear9lgdlz5umwra5_e (sub-threshold resize overlaps its neighbours) tagged `decide` with the tradeoff the options list omitted: relayouting on release bumps `layoutVersion`, which is what `FitViewOnLayoutChange` refits on — so the fix as filed re-zooms the whole graph under the user's hands.
