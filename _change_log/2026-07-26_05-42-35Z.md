## What changed
- **New `e2e/settingsBaseline.ts`** — reset-row names are DERIVED from `src/view/settingsResetPlan` (`SECTION_RESET_SCOPES`, `SETTINGS_RESET_SCOPES[scope].label`, `ALL_SETTINGS_RESET_SCOPE`); that module is `obsidian`/`react`-free, so importing it from e2e is safe (precedent: `e2e/vicinityGraph.e2e.ts` imports `../src/engine`). Card headings are not data-driven in src, so they stay hand-written here but are keyed `Record<SectionResetScope, string>` — adding a scope is a **tsc** failure, not a silently stale test.
- **Separate `CONTROLS_PANEL_DISCLOSURES`** — the toolbar panel list differs from the settings-tab list, so one const cannot serve both. Each entry carries a `.first()` flag because `hasText` is substring-based and ancestor `<details>` also match; strict-mode semantics are unchanged per entry.
- **All three specs** (`settingsResetReview`, `settingsResetVerify`, `settingsUxVisual`) consume it; the five `toHaveCount(6)` / 6- and 7-entry name-list sites became `<CONST>.length` / the shared arrays. Card headings are now DOM-asserted (previously only a prose comment) — additive, nothing weakened.
- **`npm run check:e2e`** (`tsc -noEmit -p e2e/tsconfig.json`) added and chained from `npm run check`; the compile-time guard above was previously enforced by a tsconfig no script ran. The now-redundant `npx tsc -p e2e/tsconfig.json` line was removed from `scripts/run-e2e.sh` (every path there already runs `npm run build` -> `check`). Tradeoff: `main.js` builds now fail on e2e-only type errors.
- Docs: README Scripts table (`check`, `build`, new `check:e2e`), CLAUDE.md Commands, `docs-internal/notes/e2e-obsidian-docker-setup.md` recipe.
