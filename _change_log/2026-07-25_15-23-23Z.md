Closes ticket `nid_oy3vas85xhr34n2dby1mvows4_e`.

## Root cause

libavoid unlinks a shape's visibility data only once the shape is ACTIVE, and activation happens in `processTransaction()`. But `ShapeConnectionPin`'s constructor builds visibility edges EAGERLY. So destroying a Router with an unprocessed transaction leaves orphaned `EdgeInf`s, tripping `COLA_ASSERT(visGraph.size()==0)` (router.cpp:143). That is an Emscripten ABORT, not a catchable exception -- and since `loadAvoid()` memoises the instance, the module stayed dead for the whole session, silently rendering unrouted edges on every later rebuild.

Measured trigger: >=2 pending `ShapeConnectionPin`s (0 or 1 tears down cleanly) -- i.e. >=2 obstacles of any kind.

## Fix

Unconditional `router.processTransaction()` as the first statement of `AvoidArena.dispose()` (`src/view/edgeRouting.ts`), framed as a teardown INVARIANT of `AvoidArena`: flushing is the only teardown libavoid offers. This closes the whole class -- any throw between the first shape registration and `processTransaction()` -- not just the one known throw site. Ownership rules are untouched: no `ShapeRef`/`ConnRef`/`ShapeConnectionPin` is ever tracked or destroyed by us.

Cost: 0.007ms on the success path (redundant flush) against a ~305ms pass at the repo's 100-shape fixture.

## Rejected alternatives

- **Endpoint pre-resolution** (ticket design option 2): closes only the specific missing-obstacle hole, leaves the class open, duplicates a rule `extractEdgeRoutingInput` already enforces.
- **De-memoising `loadAvoid()` on a dead module**: impossible. `libavoid-js`'s own `AvoidLib.load()` is a load-once singleton, so re-running init returns the same poisoned instance. The abort must be prevented, not recovered from.
- **`deleteShape` then flush**: itself aborts (router.cpp:287).
- **Conditional / state-tracked flush**: over-engineering; measured to buy nothing.

## Scope honesty

The known throw site is UNREACHABLE from production today (`extractEdgeRoutingInput` filters every missing-endpoint edge and is the sole input path). This closes a latent class of session-killing failure rather than fixing a live user-facing bug.

Knowingly accepted residual: with non-finite obstacle coordinates AND an in-window throw AND <2 pins, the teardown flush now aborts where teardown previously survived. Doubly gated and unreachable; no alternative teardown avoids it. Real closure is ticket `nid_a7uwpxayt6w5vdnw8ogwskwvh_e` (raised to priority 1).

## Tests

Two real-wasm BDD tests, last two in the `LibavoidEdgeRouter with real wasm` describe in `src/view/edgeRouting.test.ts` (an in-file comment pins that ordering -- while RED they poison later tests): a second `route()` after a failing pass still succeeds, and the failing pass rejects with our own diagnostic Error instead of the abort's `RangeError`. Both verified to bite by reverting the fix. `npm run check` + `npm test` green (67 files / 866 tests, 0 wasm aborts).
