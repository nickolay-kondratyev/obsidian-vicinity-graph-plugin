Until now no Playwright spec ever called `.fill()`/`.type()` on a settings input — every spec wrote through the persistence harness. The settings tab's typed-input WIRING (debounce settle, flush on blur/close, inline rejection + invalid-regex feedback) had real-Obsidian coverage of exactly zero. The pure logic was already unit-tested; the wiring was not.

**`e2e/settingsTypedInput.e2e.ts`** types into the unified rows and asserts:
- an inverted maximum node size → inline rejection visible under the row, `aria-invalid` set, value never persisted (checked against a real `reloadPlugin()` file round trip, not the input's own text)
- an invalid regex line → the offending line is named, and the text is still stored
- `.vicinity-graph-settings-error` styling and the alert/status roles
- both flush-on-leaving paths

**`e2e/settingsWriteWindow.ts`** is the reusable pattern other specs should copy — no sleeps anywhere. A sentinel-edit ordering barrier proves the NEGATIVE ("no write landed") off the debounce queue's insertion order, and `expectFlushedAheadOfWindow` starts its clock before the keystroke so a real flush is distinguishable from the `SETTINGS_WRITE_DEBOUNCE_MS` deadline; the budget derives from that constant.

Falsifiability was proven by mutation rather than asserted: emptying `flushOnBlur`'s listener makes the blur test fail at ~468 ms ("it was the 400ms debounce timer … not the flush"); removing both flush paths fails the close test. Non-flaky at 75/75 (`--repeat-each=5`), and 12/12 for the flush tests under 64 busy processes on 32 cores — observed flush latency 12–16 ms against a 300 ms budget.

One honest caveat is documented in the spec: closing the settings window also blurs the field, so the close test gates the OUTCOME rather than `hide()` in isolation.

No product code changed. `npm run check` clean, `npm test` 1245 passed, full `npm run test:e2e` 110 passed against a real Obsidian.
