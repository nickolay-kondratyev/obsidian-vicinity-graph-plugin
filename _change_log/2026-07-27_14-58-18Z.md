Root cause it guards (ticket `nid_c5acy7gm7lj3afz0vtq79k8bx_e`): `npm test` deliberately excludes the Playwright release gate. When `998fdac` removed the folder breadcrumb it deleted the element, its CSS class, and its unit tests in one commit, so `npm test` stayed green **by construction** while `e2e/vicinityGraph.e2e.ts` went red and stayed red for 3 days across two branches — misdiagnosed as a pre-existing failure. The blind spot was general: any feature removal or CSS-class rename in `src/view/` could strand e2e assertions with no fast-loop signal.

## What landed

`e2e/selectorGuard.test.ts` — pure string scan, no Obsidian, 20 tests, ~3ms, picked up by the existing `e2e/**/*.test.ts` glob in `vitest.config.ts`. It extracts every `.vicinity-graph-*` token asserted under `e2e/**/*.ts` (page-object helpers included, so centralizing a selector cannot silently disable the guard) and fails if the class is rendered nowhere under `src/view/`. The failure message names the class, every asserting `file:line`, and the remediation.

## Decisions worth remembering

- **Producers are render code (`.tsx`/`.ts`) only, NOT `.css`** — a deliberate deviation from the ticket text, verified twice by mutation: a surviving CSS rule masks a `.tsx` rename, so a CSS-inclusive scan would have been GREEN on the ticket own acceptance criteria. No currently-asserted class is CSS-only.
- **Absence assertions exempt** via line-scoped `toHaveCount(0)` (e.g. the intentional breadcrumb-absent guard). A split absence assertion fails LOUD with a re-chain remediation rather than being silently mis-handled.
- **Interpolated class names are skipped** (a truncated `.vicinity-graph-node--${tier}` tail would otherwise be a false RED — and a false RED on the fast loop is what gets guards deleted).
- **Comments and `src/view/**/*.test.ts(x)` do not count as rendering** a class. Mid-line `//` is deliberately not stripped: a real fixture contains `.replace(/^.*\//, "")`.

## Honest limits (documented in the file itself)

Catches "the e2e asserts a selector src no longer produces", NOT "the e2e asserts text/DOM structure src no longer produces" — the `solo/` title-prefix half of the original failure is still only caught by `npm run test:e2e`. Deliberately a tripwire, not a substitute for the release gate.

Running `test:e2e` in CI on every push was considered and rejected: correct but not cheap (real Obsidian download, ~1 min/run) and no help to the local fast loop.
