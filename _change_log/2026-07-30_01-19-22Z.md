Four open bugs were ONE subsystem defect, so they were fixed as one:

- **One serial chain** — `src/shared/SerialPromiseChain.ts` (pure). Replaced the three hand-rolled chains (`PluginDataStore.writeChain`, `settingsDebounce`, deleted `settingsWriteQueue.ts`) and brought the previously UNQUEUED fourth write site (`ControlsActions`, incl. pins) onto it. Exactly one serialisation point.
- **Fresh-read writes** — `src/view/settingsWritePipeline.ts` (one instance in `main.ts`, shared by the settings tab and the in-graph panel). A control emits a `SettingsInteraction` naming ONE field; the pipeline merges it over globals read fresh from `PluginDataStore` inside its serialised slot, persists, then fans out. The `ctx` snapshot prop is gone from all panel components, so sibling-field clobbering is no longer expressible.
- **Reset drains** — `src/view/settingsResetSequence.ts`: flush → write defaults → drain → `display()`. Each step in its own tolerating slot, so a failing flush or defaults write still drains before the rebuild.
- **One fan-out rule** — already unified as `ViewsRefreshPort.refreshAllViews()`; locked by making `refreshOpenViews()` private and by a fan-out ORDERING test. All writes are global.
- **Optimistic controls** — pure `PendingEdits` + `useOptimisticValue`. A request records the burst baseline AND what the write will store, so the override releases on the real echo, on an external change, on a clamp landing back on the baseline, and on a failed write.

Also: `clampSizingNumber` extracted in `src/engine/constants.ts` so rows and the write path share ONE clamp.
