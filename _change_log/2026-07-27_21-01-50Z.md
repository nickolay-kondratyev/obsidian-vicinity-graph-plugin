Node height was purely relevance-score-driven, while the thumbnail is only revealed by a CSS container query. A low-scoring note with an image could sit at minPx (40px) and never display it.

**Fix**: `NodeSizer` now floors `sizePx` (never `sizeScore`, which is also the truncation tiebreaker) at `min(THUMBNAIL_VISIBLE_MIN_NODE_PX, maxPx)` for nodes with an image. The constant is composed, not magic: `THUMBNAIL_REVEAL_CONTENT_BOX_PX (104) + NODE_VERTICAL_CHROME_PX (2*(1+8))` = 122 — container queries evaluate the *content box*, so the naive 104 left the feature inert. Measured in Chromium: display:none at 121, block at 122.

The floor keys off the stable `firstImagePath` fact, not the resolved preview kind, so the `nodePreviewPreference` independence invariant (a preference flip stays a data-only refresh) still holds.

**Usable, not knife-edge**: the title clamps to 2 lines while a thumbnail shows, yielding the full 56px slot at 122 even with a long title and a wrapping chip strip — chosen over a ~150px floor that would pin nearly every image node at the default maxPx of 160.

**Drift guard**: `thumbnailDensityThreshold.test.ts` parses the threshold, border, padding and `container-type` out of `graph-view.css` and pins `engine === cssThreshold + chrome`. Each parse throws rather than degrading silently.

Consequence: image-heavy vicinities lay out noticeably larger (image nodes now >= 122px, was as low as 40px). `npm run test:e2e` was NOT run in any iteration — it remains the merge gate.
