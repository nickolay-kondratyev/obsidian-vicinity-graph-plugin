`package.json` had `"obsidian": "latest"`, resolving to 1.13.1 while `manifest.json` declares `minAppVersion: 1.12.4` and the e2e gate pins the app binary to 1.12.7. That drift already shipped a regression: `SliderComponent.setDynamicTooltip()` is `@deprecated` in 1.13.1 typings, but the inline readout replacing it only landed in 1.13.0 — on the supported floor the method is still live, so deleting the call blanked the value readout on all 10 settings-tab sliders.

Pinned to exact `1.12.3` — npm publishes no `1.12.4` or `1.12.7` typings (1.12.x published: 1.12.0, 1.12.2, 1.12.3, then 1.13.0), so 1.12.3 is the highest published version at-or-below the floor. Pinning slightly below the floor is the safe direction: typings can never describe an API absent from supported builds. `package-lock.json` regenerated via `npm install`; no other dependency moved.

Verified: `npm run check` exit 0 (zero TS errors on the downgraded typings), `npm test` 81 files / 1094 tests pass, `npm run build` exit 0. Confirmed `setDynamicTooltip()` carries no `@deprecated` tag in the installed 1.12.3 `obsidian.d.ts`, and the call in `src/view/VicinityGraphSettingTab.ts` is intact.

One Guardrails bullet added to `CLAUDE.md` encoding the rule. Closes ticket `nid_6kms4zn8o8c8r7g983oqlvvky_e`.
