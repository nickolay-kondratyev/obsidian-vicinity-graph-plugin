Closes ticket `nid_li45606h8uvcnjm7fss17xl1u_e`.

## Root cause (measured, not assumed)

**Plugin-side.** `VicinityGraphBuilder` constructs a fresh `ObsidianLinkProvider`
on every rebuild, which re-runs `CanvasCapabilityDetector.detect` against a
still-filling `metadataCache.resolvedLinks`:

- `fallback-required` -> `CanvasFallbackParser` reads canvas FILE nodes only
  (skipping text-node wikilinks is documented V1 scope) -> **10 edges**
- `core-indexed` -> Obsidian's own index, which includes the `test.canvas`
  TEXT node's `[[note2]]` wikilink -> **11 edges**

Node/obstacle count is 13 either way, matching the reported symptom. `sparse`
was the only affected fixture because it is the only one containing a canvas
and the first test after boot. Confirmed by instrumented measurement (5 runs),
not by hypothesis.

The suspected settle-timing race in the ticket was NOT the cause: only one
13-obstacle pass lands per observation window.

## Harness changes (`e2e/edgeRoutingEval.e2e.ts` only)

- Removed the fixed `waitForTimeout(4500)` settle. The new settle is
  condition-gated (a layout pass strictly beyond the bounce note's) plus a DOM
  cross-check that the published `edgeCount` equals the rendered
  `.react-flow__edge-path` count -- a mis-settle now throws instead of printing
  a plausible-looking wrong row. No timeout was raised.
- The canvas fixture is indexed before measuring, pinning the run to
  `core-indexed`. Pure waiting is not viable: in a fallback session the
  `.canvas` key never arrives. This is a precondition, not a mask -- it pins to
  a state real users reach, and the underlying bug is escalated, not hidden.
- `settledMetrics` reports the last heaviest pass and throws when tied passes
  disagree, replacing a silent arbitrary first-wins tie-break (V8 stable sort).

## Plugin behavior: unchanged

Whether a canvas text-node wikilink should produce an edge is a product
decision, so no `src/` behavior was touched. Two characterization tests in
`src/adapters/ObsidianLinkProvider.test.ts` document that the two regimes
differ by exactly that one edge, without asserting either is correct.
