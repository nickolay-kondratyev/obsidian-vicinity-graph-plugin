A `RoutingObstacle` carrying a non-finite coordinate makes libavoid abort inside `processTransaction()` (`Assertion failed: ang >= 0`, geometry.cpp:635). `AvoidLib` is a load-once singleton, so a single bad obstacle silently degraded every later routing pass in the Obsidian session to straight edges. The teardown-flush added by `nid_oy3vas85xhr34n2dby1mvows4_e` widened this to the dispose path as well.

FIX: `src/view/edgeRouting.ts` `extractEdgeRoutingInput` validates finiteness via a module-private `hasFiniteGeometry` and skips the obstacle -- the same "define valid input, drop what is unusable, never throw" discipline already used for nodes lacking a position and groups lacking dimensions. The dropped id never enters `obstacleIds`, so the pre-existing edge pass drops referencing edges too; that matters because `route()` throws on an edge whose endpoint has no registered shape. Validation lives at extraction, not in `route()`: the abort is on the transaction path rather than the throw path, and a pure extraction filter is unit-testable without wasm.

Zero-size and negative-size rectangles are still accepted -- libavoid tolerates them, and rejecting them would have been an unrequested behavior change. Coverage is pure by design: feeding non-finite geometry to the real wasm build in a test would abort the shared instance and poison every test after it.

REACHABILITY (the ticket left this open): reachable today, but not through the layout runners. d3-force refinement is clamped and jiggles coincident bodies apart via a seeded LCG, and no node coordinates are persisted at all. The live path is node SIZING -- `src/engine/NodeSizer.ts` computes `1 / (1 + k * minDepth)` unguarded, so `depthDecayK = -1` produces an `Infinity` size that reaches the obstacle. That upstream defect is deliberately out of scope and filed as `nid_8vmo5ibhv1bvh2ukrgmafpofj_e`; this change bounds its blast radius to a wrong node size instead of dead routing.

`npm run check` exit 0; `npm test` exit 0 (68 files / 916 tests), verified independently by the reviewer.
