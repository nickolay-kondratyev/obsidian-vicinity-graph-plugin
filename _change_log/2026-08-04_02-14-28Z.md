Review of `13ade1b..HEAD` (the `DocIdMapWarmer` work). Two issues fixed, one
test-first and proven to fail without the fix.

1. **Unbounded rescans.** The previous round refused to cache a docid MISS after
   a walk whose reads failed, on the claim that "rescanning converges: a rejected
   read means the file went away". That only holds for the vanishing-file RACE. A
   file that stays unreadable (a not-yet-downloaded cloud placeholder, a
   permission error) fails identically forever, so ONE such file plus ONE
   unresolvable docid (an orphaned pin/override — which the sweep also refuses to
   delete under the same rule) made every rebuild re-read the entire vault before
   rendering, permanently and across sessions. `DocIdMapWarmer.recordMiss` now
   forgives such a miss exactly ONCE: the race still converges on the retry, the
   permanent failure costs two full scans per session instead of one per rebuild.
   Nothing is DELETED on this judgment (the sweep keeps its stricter
   `everyFileRead` rule), so being wrong costs one pin/override unrendered until
   the next session — never lost state.
2. **"Which maps are docid-keyed" was re-derived in the build path.**
   `VicinityGraphBuilder` assembled the warm list as `pins ∪ keys(nodeOverrides)`
   itself, so a future third docid-keyed map would be warmed only if whoever
   added it remembered that call — and forgetting it silently re-opens the
   cold-map bug for the new map, with no failing test.
   `PluginDataStore.docIdKeyedDocids()` (the READ twin of `forgetDocs`) now
   answers it, so both halves of that knowledge live in the store.

Also: `scanEligibleFiles` returns `everyReadSucceeded` — for a walk that STOPS
EARLY "every file read" was never true, and only `warmAll` (which never stops
early) may read it as that. Docs refreshed (`PathDocIdMap`, architecture map).

Verified: `npm test` (1539), `npm run check`, `npm run test:e2e --
controlsRestart.e2e.ts`. The e2e assertion was confirmed REAL by flipping the
expected tier and watching it fail.
