Ticket nid_zwhec6kznw0utd9sz0n5g60ex_e.

In `e2e/settingsDependentRows.e2e.ts`, `METRIC_UNDER_TEST` carried a WHY comment asserting that `noUncheckedIndexedAccess` makes `SIZING_METRICS[0]` optional, plus an `if (... === undefined) throw`. Once `SIZING_METRICS` (`src/view/sizingMetrics.ts`) became `as const satisfies`, that claim went false and the guard went unreachable — a false WHY comment teaches the next maintainer something untrue about the type system.

Deleted both. Kept the still-true rationale (read from the shared table so a renamed metric fails HERE). Also deleted a second comment the same change falsified: the arrow-const form of `expectMetricEnabledPersisted` was justified by 'a hoisted declaration is callable before the throw above'.

Protection is not lost — it moved earlier: indexing `[0]` on an empty const tuple is a compile error.

Comment-only; no production code, no e2e baselines. `npm run check` (incl. `check:e2e`) and `npm test` (1245 tests) both green; `check:e2e` passing with the narrowing removed is the proof the throw was dead. `npm run test:e2e` not run (release gate, needs a real Obsidian binary).
