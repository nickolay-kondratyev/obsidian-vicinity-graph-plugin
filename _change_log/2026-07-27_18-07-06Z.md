Ticket nid_x6l6x07rd1d1h4cefqmnyrbec_e. Branch `settings-debounce-validation`.

Previously every keystroke in a number/text/textarea settings field wrote settings and kicked off an expensive graph rebuild.

- `src/view/settingsDebounce.ts` — injectable scheduler seam, latest-wins per field, flush on blur and on tab `hide()` so no edit is lost.
- `src/view/settingsValidation.ts` — cross-field sizing rule (`maxPx >= minPx`) plus per-line regex validation returning structured results the tab renders inline.
- `src/view/sizingRowWrite.ts` — lifts the sizing row's decide/persist logic out of Obsidian glue; the rejection decision is re-checked at flush time, so a rejected value cannot reach storage via the re-derived write.
- Rejected values stay visible in the field with an inline error rather than silently vanishing or persisting.

Sizing px and depth-decay-k upper bounds already existed in `SETTINGS_SPEC`; they are now pinned by behavior tests rather than re-added. Sliders deliberately left un-debounced (they commit discrete values).

Tests: 1053 passing / 79 files (+15). Each new guard was sabotage-checked — implementation broken, test observed failing — by both the implementer and the reviewer independently, after round-1 review caught two debounce tests that would have stayed green against a no-op scheduler.

Deferred as `[decide]` tickets: engine-level cross-field clamp, `nodeCap` ceiling, e2e typed-input coverage. Superseded ticket nid_9uu8wncncsj8l59bq17y4gujy_e closed.
