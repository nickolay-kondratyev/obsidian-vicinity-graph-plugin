Second adversarial review of the docid-keyed per-node override work (36354cd + 84e983c).

1. **PERSISTED_SHAPE_VERSION 3 -> 2 (behavior change; overturns the ticket + plan-doc instruction).** `nodeOverrides` is purely ADDITIVE: an older `data.json` simply lacks the key and gets `{}` per field. A version bump makes `parsePluginData` return defaults WHOLESALE, so it would have wiped every global setting and the pinned set for zero benefit. That is the repo's standing rule, stated twice in `persistedShapes.ts` ("Added WITHOUT a PERSISTED_SHAPE_VERSION bump") and decided twice in closed tickets (`nid_8p0nn2g34d97finokwlz3u1dt_e`, `nid_fay1hu5sxcoygizopkkg0f0d7_e` - the latter against a KEY RENAME). Bumping is reserved for a removed/renamed key. The previous entry's release-note callout is therefore VOID: nothing is discarded, nothing to announce. HUMAN: this reverses a line in `docs-internal/plan/node-sizing-rethink.md` §4 (corrected in place) and in the ticket body - one edit puts it back if you disagree.
2. **Override writes are field-agnostic.** `putNodeOverride` tested emptiness against a hand-listed `sizePx`/`content` pair (a third field would have made it DELETE an entry holding only that field) and `withoutField` rebuilt from the same literal pair (silently DROPPING a third field on any clear) - neither covered by the existing `_assertEveryNodeOverrideFieldWritable`. Now `Object.keys` emptiness + copy-minus-delete, and the written value goes through an exhaustive `storedForm` switch that fails the build on a new `NodeOverrideChange` variant. Probed by temporarily adding a field: both guards fire.
3. **`PersistenceServices.saveNodeOverride` -> `saveNodeOverrideField`** - both override entry points are field-scoped, so both are named for it.
4. **Ticket link frontmatter repaired.** The previous pass wrote `links: [[a, b, c, d]\n  e, f]`; the tool reads that list line-wise, so one link came back as `[nid_...` and two were invisible.
5. **Cold-docid-map ticket de-duplicated** against the pre-existing `docs-internal/tickets/ticket-pinned-central-status-lags-after-restart.md` (same root cause, same options). They now cross-reference; the `_tickets` one owns the fix. Its stale `resolvePinPath` reference is fixed.
