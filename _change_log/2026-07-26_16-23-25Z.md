## What was wrong

`npm run test:e2e` was RED at `e2e/vicinityGraph.e2e.ts:160` — the
`.vicinity-graph-node__breadcrumb` locator for `solo/gamma.md` never appeared. Because that
file runs `describe.configure({ mode: "serial" })`, 6 further tests never ran.

## Root cause

Not a broken feature — a **stale test**. Commit `998fdac`
("feat(node-real-estate): snug capped node width + remove folder prefix", 2026-07-23)
deliberately removed the folder prefix end-to-end: render, CSS, the `breadcrumbFolderOf`
helper, its unit tests, and the corresponding sentence in `high-level-plan.md`. The e2e
assertions were left behind.

Two independent exploration agents initially concluded the opposite ("specified but never
implemented") because they read the code and plan doc at HEAD without consulting git history.
The correction came from `git show 998fdac` and `_change_log/2026-07-23_22-16-50Z.md:17`.

## What changed

- Retired the stale breadcrumb expectations; kept the still-valid trimmed-frontmatter-title
  assertion (covered by a unit test at `src/adapters/ObsidianLinkProvider.test.ts:286`).
- Replaced the vacuous `toHaveCount(0)` sibling test with a real regression guard, relocated
  to the note1-active section (`e2e/vicinityGraph.e2e.ts:177`) whose vicinity contains the
  ungrouped non-root singleton `solo/gamma.md` — the exact surviving case. Verified
  non-vacuous empirically: temporarily re-threading the removed breadcrumb turned the guard
  RED while the prior placement stayed green.
- Corrected stale doc/ticket claims that assumed the breadcrumb still exists.
- **No `src/` behavior change** (`git diff` over `src/` is empty).
