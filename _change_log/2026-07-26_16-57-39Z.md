`CONTROLS_PANEL_DISCLOSURES` listed the panel's 5 disclosures, but the spec only
checked that each LISTED entry existed — a newly added disclosure escaped assertion
entirely. The settings tab already had no such hole.

The pin: direct-child `.vicinity-graph-disclosure > .vicinity-graph-disclosure__summary`
of `.vicinity-graph-toolbar__body`, asserted with `toHaveCount` + `toHaveText` against
the new derived `CONTROLS_PANEL_DISCLOSURE_SUMMARIES`.

The two deliberate exclusions survive for different reasons, both documented at the
baseline:
- **Advanced spacing** is nested inside Force layout, so the direct-child chain drops it
  structurally — no name to maintain.
- **Pinned centrals (n)** IS a direct child when it renders, so it is filtered out by name
  via a FULL-TEXT `^Pinned centrals \(\d+\)$` regex. Chosen over relying on this spec's
  pin-free fixture (an invisible invariant that would silently turn the count into 6), and
  over a substring filter (which would swallow a future real "Pinned centrals defaults"
  section — the very hole being closed).

Summaries are matched with tail-anchored `^…\d*$` regexes: `NodeExclusionSection` renders
an optional excluded-count badge inside its own `<summary>`, so an exact string would be a
latent flake for that one entry. Anchoring the tail keeps a prefix-preserving rename
("Depth" → "Depth & scope") failing, which the initial unanchored prefix form let through.

Verified empirically against real Obsidian, not by reasoning: a temporary 6th `<Disclosure>`
failed with `toHaveCount Expected: 5 / Received: 6`; a temporary prefix-preserving rename
failed on `/^Depth\d*$/` where the pre-tightening form still passed 16 tests. Both reverted.
`npm run check` clean, `npm test` 990 passed, `test:e2e -- settingsUxVisual pinnedCentralScenario`
18 passed. (The full e2e suite remains pre-existing RED at `vicinityGraph.e2e.ts:160`,
tracked separately as `nid_yccejkvl0ccqc77olsgg5deka_e`.)
