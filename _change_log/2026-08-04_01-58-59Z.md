Second adversarial-review round over `13ade1b..HEAD`.

**Fixed (test first, proven to fail without the fix):** `DocIdMapWarmer` gave the
sweep the rule "conclude nothing from a walk that did not read every file"
(`FullScanOutcome.everyFileRead`) but still cached a MISS off exactly that
incomplete evidence on the read path. Effect: a pinned/overridden doc whose file
read transiently rejected mid-scan stayed invisible for the whole session — the
bug the cold-map fix exists to prevent, re-entered through a narrow door. The
class doc contradicted itself about it too ("never gets stuck behind a cached
miss" vs. "invisible for the session"); it now states one rule.

Rescanning converges: a rejected `cachedRead` means the file went away between
the `getFiles()` snapshot and the read, so the next walk has one file fewer.

**Reviewed and left as-is:** the e2e de-polling in `e2e/controlsRestart.e2e.ts`
(verified — the spec passes as a plain assertion), the sweep's drop-nothing gate,
the `ChunkedWork.forEachChunkedUntil` rename, and the first-build scan cost
(already tracked as `nid_y081nezeucka9l0x3umebi5zo_e`).

**Filed, not patched:** `nid_iqna8b4j5339pjiga7kgwdnh7_e` — the MAIN doc's own
`getDocId` in `VicinityGraphBuilder.build` is the same rejecting `cachedRead`,
and `GraphViewController.runRebuild` has no catch, so that sibling call still
kills a rebuild silently. Needs a declared view-level failure policy first.
