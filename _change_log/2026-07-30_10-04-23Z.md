Ticket nid_puf4a4q6fgn5lpehh5dowfm1r_e. Two nodes at the depth boundary that link to each other used to render with no edge, because an edge existed only if the BFS traversed it.

When ON, `src/engine/CrossLinkSweep.ts` sweeps the post-truncation visible set and emits every link whose source AND target are visible, seeded with the walked visible edges — so ON = walked union induced, never a replacement. That seeding is load-bearing: the outgoing and incoming channels are independent provider authorities that can diverge, so an outgoing-only replacement could DROP an edge the OFF graph drew.

Node selection and distance ranking keep running on the walked edge set — cross links only widen edges, never change which nodes are visible. Cross links render identically to walked edges (same xN count path, no styling seam). OFF is byte-for-byte the previous graph.

Deviation from the ticket text: its "global / MAIN / pinned cascade" wording is stale — settings are global-only, so this is a plain global boolean on the declared-row model, picked up by both presenters by construction. Row lives in a new "Edges" settings section.
