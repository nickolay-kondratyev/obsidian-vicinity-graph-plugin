Hostile sizing settings could produce non-finite `sizePx`: `depthDecayK = -1` with `minDepth = 1` made `1/(1 + k*minDepth)` divide by zero, and `1e999` parsed to `Infinity` past the old `minPx`/`maxPx` guards. That flowed through `nodeDimensionsPx` into `FlowNode.width/height` and rendering, and the affected edges were silently dropped from routing.

Fix follows the existing `clampForceLayoutSettings` precedent: bounds are declared once in `src/engine/SettingsSpec.ts` (`depthDecayK [0,10]`, `minPx`/`maxPx` `[1,400]`, `metricWeight [0,100]`) and applied by a new `clampSizingSettings` on load, on write (`planSettingsWrite`) and inside `NodeSizer`. `DepthDecayMetric` keeps a last-line finite guard, now pinned by direct tests.

Also extracted `src/view/sizingInput.ts` `parseSizingInput` as the single input rule for all four UI number inputs — this fixed a regression where a cleared field (`Number('') === 0`) would persist a clamped `1`.

Correction to the ticket's premise: the `depthDecayK = Infinity` case was never reachable — `minDepth === 0` implies `isCentral`, and centrals bypass metrics. The real reachable defects were `k = -1`, `k = NaN`, non-finite `minPx`/`maxPx` and an `Infinity` metric weight.

Verified: `npm run check` exit 0; `npm test` 72 files / 966 tests / 0 failures.
