Adversarial review of the content-fit sizing change (nid_cx5zoz7ptucg9nxalibv0mbjb_e).

- **Fixed (correctness):** `NodeSizer` summed the regions it decided to show, but the stylesheet paints the preview slot (outline OR thumbnail) only above a 104px content box and the attachment chip row only above 72px. A note with 1-4 renderable headings grew to 57-111px and then showed a title plus dead space, no outline; a title-only note with an attachment did the same at 61px. `NodeSizer.revealFloorPx` now floors any preview-bearing node at `PREVIEW_VISIBLE_MIN_NODE_PX` (122px) and any attachment-bearing node at `ATTACHMENT_ROW_VISIBLE_MIN_NODE_PX` (90px) — the rule the thumbnail already had, now shared. `minPx`/`maxPx` still clamp on top.
- `THUMBNAIL_VISIBLE_MIN_NODE_PX` renamed to `PREVIEW_VISIBLE_MIN_NODE_PX` (one slot, one threshold); `thumbnailDensityThreshold.test.ts` became `nodeDensityThresholds.test.ts` and now pins BOTH rungs (and that the outline and thumbnail share one) to the stylesheet.
- **Fixed (false test):** `GraphTruncator.denseFixtures.test.ts` still had a "sizeScore decides" case that passed only by the path fallback after the score level was removed; replaced by a case that asserts bytes rank nothing, and its fixture is ordered so a resurrected size level would fail it.
- Dead metric-row CSS removed; stale references to the removed dials, to `nodePreviewChoice` (now `engine/nodePreviewKind`) and to the old constant/test names updated across source, plan, architecture map and open tickets.
- **Owner decision filed:** `nid_1mq3t7706vw2kj2kv7ljqlw6l_e` — the floor means every note with one heading is now 122..160px at shipped defaults; the alternative is lowering the CSS rungs so small outlines paint at their true fit.

Verified: `npm test` (1562), `npm run check`, e2e nodeOutline + vicinityGraph + edgeRouting + pinnedCentralScenario.
