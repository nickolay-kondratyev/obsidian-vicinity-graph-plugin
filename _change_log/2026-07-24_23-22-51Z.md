No production code changed. `edge-routing__05` aimed to stop over-stretched wrap-around
edge routes by making facing-side group pins cheaper via
`ShapeConnectionPin.setConnectionCost()`.

## Why it closed without code

Measured against the real libavoid wasm before implementation: facing-side pin costs change
**0 of 818 group attachments** across 400 random crowded scenes, and are still 0 at cost
100 000. A positive control passes, so the API is live and correctly bound.

Root cause: the facing pins are **visibility-BLOCKED** by the 17px per-obstacle shape
buffer, not near-ties. **No cost bias can reach a pin the router cannot see.** A second
agent independently re-ran the probes; every number reproduced exactly.

## Other findings

- PREREQ spike answered: `setConnectionCost`, `setExclusive`/`isExclusive`, `directions`
  and `portDirectionPenalty` are all bound in `libavoid-js@0.4.5` — no wasm/WebIDL rebuild.
  `Avoid::ClusterRef` is NOT bound, so `clusterCrossingPenalty` is infeasible on 0.4.5.
- Ticket Design step 2 (`setExclusive(true)`) was a no-op — directional pins already default
  to exclusive. The useful move is the opposite, `setExclusive(false)`, which also fixes a
  latent bug live today: with 3 pins per side, the 4th edge approaching a side silently
  falls back to the group centre.
- A keep-shorter route rule structurally cannot fix these cases: a wrap-around wins the
  baseline pass precisely because it is shorter.
