Nodes inside folder groups were spread out, wasting space (ticket nid_uzwco7e4y2bw5vzfk5vhs814a_e).

**Two independent causes, both fixed.**

**1. Wrong algorithm.** Group interiors were laid out by elk `layered`, which optimizes edge flow rather than density — and this repo discards elk's edge routing entirely (edges are routed by `edgeRouting.ts` via libavoid), so layered's whitespace cost bought nothing. Interiors now use elk `rectpacking` (`aspectRatio 0.75`, `orderBySize`), which is purpose-built to pack heterogeneous rectangles.

**2. The gap — the bigger cause.** Real-vault testing showed groups still looked airy. Measurement explained why: at the old 40px member gap the members' gap-expanded rectangles alone put a hard ceiling of ~0.58 on interior fill, so *no* packer could have helped. A custom skyline packer was written and measured to confirm this, then rejected (within ~5% of elk, worse on a 13-member group). The fix was the gap: `elkNodeSpacingPx` default 40 → 20 — the first slider-grid value at or above the group's own 16px side padding, so members are never farther from each other than from the group wall.

**Measured result** (interior fill = member area / padded box area):

| Group shape | Before | After |
|---|---|---|
| 5-member real-vault case | 433x459, 0.509 | 413x419, **0.591** (-13% area) |
| 13-member hub / chain / edge-free | 702x523, 0.515 | 602x483, **0.660** (-21% area) |

Box size is now identical regardless of intra-group link topology — the durable win, and it feeds a smaller, more predictable collision rectangle to the root d3 pass.

**Spacing knob split.** `elkNodeSpacingPx` previously fed both the group interior and the root force seed; lowering it blew a root stranding budget. The root seed is now pinned to an internal `ELK_ROOT_SEED_NODE_SPACING_PX = 40` (no new user setting, root pass byte-identical for default users, locked by a literal-value test). Accepted trade-off, human-approved: a user with a saved non-default value gets it applied inside groups only, matching the slider's existing "Group member spacing" label.

**No migration**: existing installs keep 40 in `data.json` and pick up the new default via "Restore force layout defaults" (deliberate — plugin is pre-release).

New `src/view/groupPacking.test.ts` locks fill floors and topology-independence. A pre-existing `minHalfExtent()` stranding bug with landscape containers was found and measured (rectpacking 113px vs layered 130px against a 100px budget — i.e. rectpacking *improves* it), pinned with `it.fails` plus follow-up ticket nid_y45ndtq65f15pnrwfvpgz5pks_e.
