Ticket nid_9ep12hkmk4zjv2p28emmrhieq_e. New pure module src/view/layoutFit.ts answers ONE question over the geometry the reuse path would keep (absolute positions + elk folder-group boxes, both already held by GraphViewController): does each resized node's NEW box, at its EXISTING top-left, still clear its neighbours, stay out of other groups' boxes, and stay inside its own group's border? Anchoring at the old top-left is exact — only right/bottom/corner grips exist, so a resize never moves the origin. GraphStructureDiff's anySizeOverrideChanged became resizedPaths (same sameNodeSizeOverridePx equality seam) and the unconditional relayout became 'resized && !fits'; decideLayout takes the rendered layout as a 4th arg. The growth threshold now SKIPS a just-resized node, so a big-but-fitting resize cannot relayout through the back door. Conservative on unknown geometry (no layout yet / missing position) = relayout. Side benefit: a fitting resize no longer bumps layoutVersion, so it no longer refits the viewport — shrinks nid_ct22qotgtw4rezbdn5m0diyb3_e to the colliding case. 11 new BDD cases + an e2e tripwire verified to fail against the old rule.
