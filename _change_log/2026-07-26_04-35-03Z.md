One BDD test in `e2e/settingsUxVisual.e2e.ts`: hover the "Outline depth" slider, assert its runtime `inputValue()` is visible as RENDERED TEXT in either the body-level `.tooltip` (pinned 1.12.7 runtime) or the row `.setting-item-control` (Obsidian >= 1.13, where the readout moves inline). Mechanism-agnostic, so a future `minAppVersion` bump needs no edit.

Deliberately not satisfiable by the `<input value=...>` attribute (text-only match), by a digit in the row name/desc (scoped to `.setting-item-control`, exact match), or by a stale tooltip from an earlier test in this serial file (`page.mouse.move(0, 0)` before hover). The interpolated value is regex-escaped so a fractional step cannot match loosely.

Teeth verified empirically: deleting `.setDynamicTooltip()` from `addLabeledSlider` makes the test fail (neither union arm resolves); restoring it makes it pass. `src/view/VicinityGraphSettingTab.ts` gains a comment-only `@see` pointer from the WHY doc to the guarding test, since the `@deprecated` tag will tempt the next maintainer again.

Verification: settingsUxVisual 15/15, `npm run check` clean, `npm test` 966/966.

Known gap: the >= 1.13 inline arm has never executed on a real 1.13 build.
