`GraphViewController.resolveRoutes()` guarded its routing-failure warning with a
`routingFailureWarned` boolean that was never reset, so the FIRST failure muted every
later one for the controller's whole lifetime — including failures with a completely
different cause, while edges quietly rendered straight.

That latch is now `warnedRoutingFailures: Set<string>`, keyed by a failure signature
(`name: message` for an `Error`, otherwise `String(error)`). Flood protection is
preserved — a repeat still warns once — but a NEW kind of failure warns again.

Stringification itself is guarded: `EdgeRouter.route()` has no typed error channel, so
the catch sees `unknown`. A null-prototype or hostile-`toString` throwable must not let
the failure REPORTER throw and take down the rebuild.

Deliberately rejected, with rationale recorded in the branch's `.ai_out/` docs:
- capping the signature set — would reintroduce the exact swallowing bug being fixed
- `JSON.stringify` for plain-object throwables — speculative, needs its own cycle guard
- debug-level for repeats (the ticket's stated alternative) — per-signature dedup keeps
  every distinct signal at warn level, which is where it belongs

Stale "warn ONCE" wording on the field and on the `resolveRoutes()` doc comment was
corrected so the docs no longer misstate the behavior.

7 new BDD tests in `src/view/GraphViewController.test.ts` using the existing
`FakeEdgeRouter`. The pre-existing "warns exactly once" behavior-capturing test is
byte-identical and still green. The reviewer mutation-verified in a throwaway worktree
that the new tests fail against the old boolean latch and against a bare `String(error)`,
confirming they discriminate for the right reason rather than passing incidentally.

Gates: `npm run check` exit 0; `npm test` 68 files / 922 tests passed.
