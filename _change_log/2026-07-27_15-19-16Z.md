The controls-panel exhaustiveness pin in `e2e/settingsUxVisual.e2e.ts` (`topLevelPanelSummaries`) deliberately filters the conditional "Pinned centrals (n)" disclosure out by name — which left the suite blind to a regression where that disclosure renders UNCONDITIONALLY. The two pinning specs only asserted PRESENCE after a pin.

- New BDD test in `e2e/settingsUxVisual.e2e.ts` asserts `toHaveCount(0)` for a top-level summary matching the anchored `^Pinned centrals \(\d+\)$` shape on a view with nothing pinned. Kept as a single chained statement so `e2e/selectorGuard.test.ts` exempts it.
- Extracted `PINNED_CENTRALS_SUMMARY_PATTERN` and `TOP_LEVEL_PANEL_SUMMARY_SELECTOR` into `e2e/settingsBaseline.ts` so the existing exhaustiveness filter and the new assertion share ONE definition; the filter's semantics are unchanged.

**Mutation-verified on the real gate**: with the `pinned.length > 0 &&` guard removed in `src/view/GraphToolbar.tsx`, the new test failed `Expected: 0 / Received: 1` while the exhaustiveness test stayed green — proving the blind spot was real. Mutation reverted; `src/` is untouched by this change.

Gates: `npm test` 1010 passed, `npm run check` clean, `npm run test:e2e -- settingsUxVisual.e2e.ts` 17 passed (re-run independently by the reviewer), pinning specs still green.
