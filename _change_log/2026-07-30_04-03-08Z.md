Ticket nid_fay1hu5sxcoygizopkkg0f0d7_e, Stage 1 ("carry the kind, change no behavior").

- `LinkKind = "link" | "embed"` lives in `src/shared/LinkKind.ts` (below the engine, because the shared regex matchers name it) and is re-exported from `src/engine/index.ts`.
- `LinkProvider.getOutgoingReferences(path)` is the new outgoing truth: `{target, kind}`, deduped per (target, kind). `getOutgoingLinks` is its kind-blind view in both providers, so every existing outgoing assertion is untouched.
- Kind sources: markdown array provenance (`cache.embeds` vs `cache.links`), frontmatter always `link`, canvas file node always `embed`, canvas text node from the now-captured `!` in `Wikilinks`/`MarkdownInlineLinks`.
- ALWAYS-PARSE CANVASES: `resolvedLinks` is never consulted for canvas links, so kinds are not boot-timing-dependent. `CanvasCapability.ts` deleted. Permanent fix shape for closed ticket nid_s676x55uojmtcwh9t4l9mc6zl_e.
- `getLinkCount` stays kind-blind on purpose (resolvedLinks is a merged count; splitting it would risk changing a rendered badge).
- Nothing consumes the kind yet — traversal, settings and UI are untouched (Stage 3's job).

## Notes

**2026-07-30T04:14:19Z**

REVIEW ITERATION — one BEHAVIOR CHANGE that the original entry did not disclose.

Canvas EDGE COUNTS switched source. Before always-parse, a canvas that Obsidian core
had already indexed had no entry in canvasOutgoingByPath, so getLinkCount fell through
to resolvedLinks — core's number. Now every canvas is parsed, so the rendered
edge-count badge is OUR occurrence count for EVERY canvas. Canvases ARE core-indexed on
a stock 1.12.7 install, so this is the live path.

KEPT, not reverted, and the reason is coherence: the edge SET already comes from our
parse, so sourcing the COUNT from core would split one edge across two authorities and
re-expose the badge to the canvas-indexing boot race that always-parse was adopted to
kill. One authority per edge. Pinned by a test whose seeded resolvedLinks (1) disagrees
with the parse (3), so a future divergence fails in unit tests, not in e2e.

User-visible effect: on a canvas where core coalesces references that we count
separately (or vice versa), the edge badge number can differ from before. The edge SET
is unchanged.
