Closes the last cheap regime difference from the canvas link unification.

Canvas text nodes are markdown, so Obsidian core indexes markdown-style inline
links written there; the fallback parser only harvested wikilinks, so the two
regimes disagreed. New pure `src/shared/MarkdownInlineLinks.ts` normalises a
markdown destination to LINK TEXT and reuses the same `getFirstLinkpathDest`
seam wikilinks already use — one resolver, no new `CanvasReference` kind.

Order of operations is load-bearing: the external-URI verdict and the `#`/`?`
strip happen BEFORE percent-decoding, so `note%3Aone.md` is not mistaken for a
URI scheme. An unencoded space in a bare destination yields NO edge (CommonMark:
not a link) rather than silently truncating to a wrong-but-resolvable target —
a wrong edge is worse than a missing one; a whitespace suffix counts as a title
only when it opens with `"`, `'` or `(`.

The premise that core indexes these links was observed, not assumed:
`e2e/canvasMarkdownLinkIndexing.e2e.ts` reads core's own `resolvedLinks`
against real Obsidian 1.12.7.

Code-span / fenced-code awareness stays out of scope, tracked separately.
Docs corrected: plan doc 'Canvas support', `Wikilinks.ts` header, and a README
line that was already wrong before this change.
