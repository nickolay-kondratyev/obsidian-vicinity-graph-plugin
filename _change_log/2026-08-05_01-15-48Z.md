Found reviewing `a150312..HEAD` (content-fit node sizing, ticket nid_cx5zoz7ptucg9nxalibv0mbjb_e).

1. **Reveal floors were 2px short for centrals.** `[data-tier="main"]` / `[data-tier="pinned-central"]` draw a 2px accent ring, so a central's container-query CONTENT box is `sizePx - 20`, not `sizePx - 18`. Content-fit sizing lands a central exactly ON the floor routinely (a MAIN note with 1-4 headings), so at 122px it got a 102px content box, missed the 104px query, and rendered a title over 40px of dead space — the exact trap the floor exists to prevent. Safe to ignore before this change only because centrals used to be pinned to `maxPx`.
   Fix: `revealMinNodePx(rung, isCentral)` in `src/engine/constants.ts` is now THE one place `rung + chrome` is spelled out; `NodeSizer` sums and floors with the node's own chrome. `src/view/nodeDensityThresholds.test.ts` now parses BOTH `[data-tier]` borders, so the central chrome cannot drift either.

2. **The thumbnail slot was never counted**, though `NodeSizer`'s own docstring said it was. A thumbnail node that also carries a chip row and a wrapped title needs `title + 56 + chips`; sized without the slot it landed on the 122px floor and pushed the chip row out through `overflow: hidden`. Fix: `ESTIMATED_THUMBNAIL_SLOT_PX` is a counted region, and the title is budgeted the 2 lines the reveal block clamps a `[data-preview="thumbnail"]` title to (`THUMBNAIL_PREVIEW_TITLE_LINE_CLAMP`). Both mirrored constants are guarded against the stylesheet by the same density test.

3. Stale comments corrected: the e2e/dev-vault fixture notes still claimed an outline-bearing node is 93px (it is floored at 122px), and `sizingRowWrite.ts` still justified the cross-field row set with the removed `depthDecayK`.

`npm test` (1568), `npm run check`, and `npm run test:e2e` for nodeOutline / vicinityGraph / pinnedCentralScenario / edgeRouting are green.
