Closes `nid_hatwq2jlkhno5t6awcz0q6t9q_e` (which absorbed `nid_9jiira82snkh7bgy8zv060c9r_e`, the engine
half of the same invariant). Implements the owner's decision recorded on the ticket: **raise, never swap**.

## Engine

`clampSizingSettings` (`src/engine/constants.ts`) now raises `maxPx` to the *clamped* `minPx` when the
pair is inverted. That is the single choke point already run by `NodeSizer.compute`, `parseSizing` (load)
and `planSettingsWrite`, so one rule closes all three doors. Previously a hand-edited `data.json` — or the
in-graph panel — could store `minPx=400, maxPx=40` and get a finite but INVERTED size ramp (higher score →
smaller node).

## Controls panel

The panel's typed rows (`SizingNumberRow` min/max/k and `NodeCapRow`, via the shared `NumberRow` in
`src/view/SettingsRowView.tsx`) were fully controlled and wrote on every `onChange`, so clamping snapped
the field mid-keystroke and `NodeCapRow` could not even be backspaced to blank. They are now
uncontrolled and commit on blur/Enter, and an inverted pair is REFUSED with the settings tab's own
`describeSizingRejection` copy, `aria-invalid` and `aria-describedby` — bringing the panel to parity with
the tab, which was fixed earlier via `settingsDebounce.ts`.

The blur decision lives in a new pure seam, `src/view/numberRowCommit.ts` (`NumberRowCommit` with
`writing` / `refusing` / `nothing` factories and a derived `reseedsFromStore`), so it is covered by BDD
unit tests without rendering React — `npm test` still renders nothing.

Cross-field validation reads the store FRESH through a new `ControlsActionsPort.storedGlobalView()`
rather than judging against the rendered snapshot, per the settings rule in CLAUDE.md.

## Behaviour-capturing tests changed (explicitly authorised on the ticket)

- `src/engine/NodeSizer.test.ts` — the test that PINNED the inverted ramp as accepted behaviour was
  rewritten to assert the raise-max rule, and relocated out of the image-floor `describe`.
- `src/view/numberRowCommit.test.ts` — "WHEN a value is written THEN the field is NOT reseeded" was
  rewritten: a capped or respelled write leaves an unstored number in the box with no message, so any
  non-refused commit now reseeds from the store.
- Two spec-walking tripwires were amended in the open (not weakened) for the new cross-field repair:
  `settingsSpecPersistence` names the one declared repair, and the `settingsRowAccessors` round-trip
  probe writes at the range ceiling. The repair itself is pinned independently by new `persistedShapes`
  tests, and the amendment is directional — a swap implementation would still fail.
