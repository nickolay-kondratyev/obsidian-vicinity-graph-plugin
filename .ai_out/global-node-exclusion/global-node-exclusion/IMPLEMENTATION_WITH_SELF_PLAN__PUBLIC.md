## What was built (by layer)

### Engine (pure — import-guarded, no obsidian/react)
- **`src/engine/PathExclusionMatcher.ts`** (NEW): cohesive pure class. `fromPatterns(patterns)`
  compiles each with `new RegExp(pattern)` (case-sensitive, no flags), **silently skips**
  invalid ones; `excludes(path)` = ANY compiled regex `.test(path)` (UNANCHORED, full path
  incl. extension). Empty/all-invalid ⇒ no-op matcher.
- **`VicinityTraversal.ts`**: constructor takes an optional matcher (default no-op). `traverse`
  computes the root-path set once and threads it to `bfs`. At neighbor discovery, exclusion is
  checked **before** `isNodeBearing` (so an excluded neighbor never reads metadata, never
  records an edge, is never enqueued/expanded — the perf win); **roots are exempt** (a matching
  path that is also a root passes through). Distinct excluded paths are collected in a `Set` →
  `TraversalResult.excludedNodeCount`.
- **`VicinityEngine.ts`**: `GraphBuildRequest.nodeExclusion?: NodeExclusionSettings` (passed
  WHOLE, like `globalView`). Engine gates on `enabled` (`private exclusionMatcher`) and threads
  `traversal.excludedNodeCount` onto `VicinityGraph.excludedNodeCount`.
- **`types.ts`**: `NodeExclusionSettings { enabled; patterns[] }` (settings shape, sits with
  DepthSettings/ViewSettings); `VicinityGraph.excludedNodeCount: number`.
- **`constants.ts`**: `EngineDefaults.nodeExclusionSettings()` → `{ enabled: false, patterns: [] }`.
- **`index.ts`**: exports `PathExclusionMatcher` + `NodeExclusionSettings`.

### Persistence
- **`persistedShapes.ts`**: `PluginData.nodeExclusion`; default via `EngineDefaults`; defensive
  non-throwing `parseNodeExclusion` (non-object/non-boolean-enabled/non-array-patterns degrade to
  default; only string patterns survive). **Version stays v1** (additive).
- **`PluginDataStore.ts`**: `nodeExclusion()` getter + `saveNodeExclusion()` setter (serialized
  write chain, same pattern as `saveGlobalView`).

### Adapters
- **`GraphRequestAssembler.ts`**: `GraphRequestInputs.nodeExclusion`; passed straight through to

- **`VicinityGraphBuilder.ts`**: loads `pluginDataStore.nodeExclusion()` into inputs; threads
  `graph.excludedNodeCount` into `ControlsModelBuilder.build(inputs, count)`.

### View

## Semantics (as shipped — reviewer quick-reference)
- Match: `regex.test(vaultPath)` — UNANCHORED, CASE-SENSITIVE, full path incl. extension. `rel/`
  matches `rel/x.md` and `a/rel/x.md`; `^rel/` anchors to vault root. Invalid regex → skipped.
- Excluded iff ANY enabled+valid pattern matches. `enabled=false` or empty list ⇒ no-op, count 0.
- **Roots exempt**: main + pinned centrals are never excluded even if they match (verified by test
  incl. the case where a matching path is a pinned root reached as MAIN's neighbor → stays, count 0).
- Count = distinct vault paths rejected during THIS traversal; surfaced next to the pill only when
  enabled AND > 0.

## Callouts / notes for reviewers
- **Exclusion checked before `isNodeBearing`** (perf: excluded neighbors skip the metadata read).
  Consequence: if a pattern matches an ATTACHMENT path reached as a neighbor, it is counted too.
  In practice patterns are note-oriented and attachments surface via their linker's metadata (not
  as neighbors), so there is no behavioral regression — only a possible count contribution. Flagged
  for awareness; matches the literal "distinct vault paths rejected by exclusion" wording.
- **Documented semantic** (from CLARIFICATION): a node reachable ONLY through an excluded node is
  not discovered — this is the intended data-layer behavior, not a bug.
- No per-doc override, no settings-tab regex validation UI (invalid patterns silently skipped) —
  both explicitly out of scope this iteration.
- Not committed; working tree holds all changes. `main.js`/`styles.css` were regenerated by the
  build step (artifacts).
