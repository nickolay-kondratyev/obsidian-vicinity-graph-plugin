# Research: removing the `fetch(` network-risk tokens from `main.js`

Scratch research notes backing the spike ticket (`nid_...` — libavoid node-build
switch). Temporary — under `notes/tmp/`, not a spec. Delete once the ticket lands.

## Problem

The Obsidian community-plugin scanner flags **2 network calls** and shows a
user-facing "risk" badge. Both `fetch(` tokens live in the bundled `libavoid-js`
web build (Emscripten glue). They are a **false positive at runtime** — we load
the wasm from an embedded `data:` URL, zero network egress (see closed ticket
`nid_snrc13nuv21y30lv26m9z1e3c_e`). But the badge is generated by a **static text
scan of the shipped `main.js`**, so a human "it's a false positive" disclosure
does NOT clear it. The tokens must be genuinely absent from `main.js`.

WASM itself is required — edge avoidance is core rendering. Not droppable.

## Three ways to make the tokens absent (ranked by effort)

1. **Switch to the libavoid-js NODE build (PREFERRED — the spike).** The package
   already ships `dist/index-node.mjs` with **zero `fetch(` / `XMLHttpRequest` /
   `instantiateStreaming` tokens** (verified by grep). It loads wasm via
   `createRequire` + `readFileSync`, exposes the SAME `AvoidLib.load()` /
   `getInstance()` API, and still honors `wasmBinary`. The `exports` map has a
   `"node"` condition pointing at it:
   `"exports": { ".": { "node": "./dist/index-node.mjs", "default": "./dist/index.js" } }`.
   We currently resolve `default` (the web build). Flip esbuild resolution to the
   node entry + feed the embedded bytes as `wasmBinary`. No Docker, no patching.

2. **Build-time strip of the vendored web glue.** esbuild transform rewrites the two
   `ae`-guarded ternaries so the `fetch(<ident>,{credentials:"same-origin"})`
   operand is gone (replace with a non-network stub; site 1's `.catch(()=>Ge(e))`
   already falls back to a binary read). Fragile across `libavoid-js` version bumps;
   guarded by a token test. Fallback if option 1 fails.

3. **Recompile libavoid with `-sENVIRONMENT=node`.** Upstream `Aksem/libavoid-js`
   v0.4.5 builds via `python3 tools/generate.py` in Docker image
   `emscripten/emsdk:3.1.36`; Adaptagrams C++ auto-cloned (`Aksem/adaptagrams`
   `v1.0.4`). `ENVIRONMENT` is ALREADY a parameter (web|node). One portable `.wasm`
   for all platforms (WASM is CPU/OS-independent — NOT a per-OS matrix). Cost is
   owning the Docker toolchain + version. Heaviest; only if 1 AND 2 both fail.

## Current wiring (what the spike changes)

- `esbuild.config.mjs`: `libavoidWasmPlugin` maps the virtual id `libavoid-wasm`
  → `dist/libavoid.wasm`, inlined base64 via `loader['.wasm']='base64'`.
- `src/view/libavoidLoader.ts`: `AvoidLib.load(WASM_DATA_URL)` (data: URL) →
  `AvoidLib.getInstance()`. This is where the entry point + byte injection changes.

## Open questions for the spike

1. **Byte injection into the node build.** `index-node.d.ts` types `load(filePath?:
   string)`. Confirm we can inject the embedded bytes (Module `wasmBinary` /
   `locateFile` override, else `Module.instantiateWasm`). A single-file plugin bundle
   has NO on-disk wasm path, so relying on the node build's default `readFileSync`
   is not an option — injection must work.
2. **Does the node build run in Obsidian's Electron renderer?** High confidence yes
   (Obsidian plugins have node integration: `process.versions.node`, `require`,
   `createRequire` all work), but must be proven by e2e that actually instantiates
   the wasm and renders routed edges.
3. **New-token check.** Confirm `readFileSync` / `createRequire` don't trade the
   network badge for a DIFFERENT/worse Obsidian risk flag. The plugin already does
   vault file I/O, so node/fs surface is not conceptually new — verify against the
   scanner's actual categories. If injection makes the `readFileSync` path dead we
   may still want it token-absent.

## Acceptance signal

- `grep -E 'fetch\(|XMLHttpRequest|instantiateStreaming' main.js` → **0 matches**.
- A token guard test over the BUILT `main.js` (pattern of the existing
  `importGuard.test.ts` guards) makes that invariant CI-enforced.
- Existing edge-routing e2e stays green (wasm instantiates, routed edges render).
